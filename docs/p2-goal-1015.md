## 6. P3 独立 ACL Harness 设计

只使用已经冻结的 P2 编译产物作为设备程序。

必须明确：

- `kernel.o` 的完整 SHA-256、ELF 类型、目标架构和 Kernel symbol。
- 与当前 CANN 9.2 环境中 ACL Binary Loader 的格式兼容性。
- 三个 GM 指针参数的实际排列与 HostArgs 打包。
- grid=64。
- dynamic UB=196608 bytes。
- A/B/C 的 f32 数据规模各为 524288。
- Stream 创建、同步、超时、ACL 错误与资源释放机制。

形成可以直接实现的 C++ ACL Harness 设计，不调用 TileLang 的 CodeGen 或 Runtime。

设计至少三个输入集：

1. 全零与非零常量，验证基本计算正确性。
2. 正负混合、不同数量级的 f32 输入，检查计算和同步。
3. 每 block 具有不同特征的数据，验证 64 个 block 的索引、GM 偏移及块边界。

要求：

- 全部 524288 个结果逐元素比较。
- 输出在启动前初始化为明显不同的哨兵值，检测未写入元素。
- 在允许的分配布局下使用前后 guard 区域，检测越界写。
- 核对 8191/8192、16383/16384 等 block 边界。
- 检查完成同步，不能在异步执行结束前读取结果。
- 收集 ACL 错误码、最近错误信息和设备日志。

如果 ACL Loader 无法加载 P2 的 `kernel.o`，优先核实二进制文件格式和导出符号，不能换用旧 AscendC/PTO Binary 伪装 P3 成功。

## 7. P4 交接约束

P3 允许显式配置 grid 和动态 UB。

P4 必须通过现有 TileLang 的 `ExtractFuncInfo`、`AscendModuleCreate`、`launch_param_tags` 和 `aclrtLaunchKernelWithHostArgs` 自动传递启动配置。

不得假定 `hacc.block_dim` 已被 TileLang Runtime 消费。

P5 必须从 Golden Prepared TIR 正式生成 Late IR，包括：

- UB f32 元素偏移转 byte 地址。
- pb32 显式载体。
- cache4。
- VF outline 与调用。
- set/wait 同步。
- 末尾 PIPE_ALL。

这些都是后续阶段，不允许本轮提前实施。
