## 6. P3-B：独立 Kernel Launch

在 P3-A 通过后，扩展 Harness。

固定设备入口：

`main_kernel(A, B, C)`

HostArgs 为三个 64-bit GM 指针，按 A、B、C 顺序连续打包。

必须具有编译期检查：

- sizeof(HostArgs) == 24。
- A/B/C 的 offset 为 0/8/16。
- 不额外传入 blockIdx、grid 或 UB 指针作为 Kernel ABI 参数。

固定启动配置：

- numBlocks = 64。
- dynamic UB = 196608 bytes。
- 单设备、单 stream。
- HostArgs placeholders = 0。

注意：HostArgs 中存放设备 payload 地址，不是主机数组地址，也不是指针数组的主机地址。

第一版优先使用与 TileLang 现有 Ascend Runtime 一致的最小 launch 配置：动态 UB 属性。

若需显式 ENGINE_TYPE=AIV 或 TIMEOUT 属性，先核对本地 ACL 头文件，再通过有界实验证明其必要性，记录所选配置。不得未经说明静默增删关键属性。

Kernel 启动返回成功不等于执行成功。

必须等待专有 stream 同步成功，并且只在同步成功后读取设备输出。

P3-B Gate：

- launch rc=0。
- synchronize rc=0。
- 没有未解释的设备执行故障。
- dynamic UB 和 grid 均使用预期值。
- 所有资源生命周期受控。

同步失败或超时后，不得继续读取未完成的输出，不得在 Kernel 仍可能访问设备内存时释放其 buffer。

P3-B 未通过，不得进入 P3-C。

## 7. P3-C：全量数值正确性

### 7.1 数据几何

固定：

- N=524288，dtype=float32。
- 64 AIV blocks。
- 每 block 8192 元素。
- 每 block 128×64 向量运算。
- A/B/C 每数组 2097152 payload bytes。
- UB byte bases：0 / 65536 / 131072。
- GM DMA payload：32768 bytes。

不得将 `UB_SIZE=2031616 bits` 当作 dynamic UB launch 参数。

### 7.2 独立 Oracle

Verifier 先实现独立 Host 数值预期，且不读取 Implementor 的输出计算逻辑来生成预期。

至少使用现有 `docs/p3-acl-harness-design.md` 中的全部数据族：

1. Constants：全零、零+非零、不同非零常量。
2. Mixed：正负混合、不同数量级、抵消。
3. Per-block：每个 block 的输入明显不同，并具有不同的边界特征。

输入由确定性公式生成，记录数据版本、种子或公式参数。

所有输入先转 float32，reference 按约定的 float32 加法舍入语义计算。

输出全部是有限数；若设备输出出现 NaN/Inf，直接失败。

对于本轮受控数据，要求有限结果逐元素数值精确相等，允许 +0/-0 的数值相等。

每个 case 至少重复 3 次。

### 7.3 全量比较与内存保护

每组输入运行前：

- A/B 写入新的确定性输入。
- C 全部初始化为固定 NaN-bit sentinel `0x7fc12345`。
- A/B/C 均分配前后 guard 区，默认 256 bytes。
- Guard 初始化为固定字节 `0xa5`。
- 核实 payload 实际地址满足 DMA 对齐要求。

每次同步成功后：

1. 比较 C 全部 524288 元素。
2. 检查 C sentinel 是否有残留。
3. 检查 A/B payload 是否被修改。
4. 检查六个 guard 区域是否改变。
5. 每个 block 单独报告 mismatch 数量。
6. 特别报告 block 起点和终点。
7. 记录首次 16 个错误及最大绝对误差。

必须覆盖 8191/8192、16383/16384，以及最后一个元素 524287。

Guard 测试只能证明本次分配布局中邻近保护区未被破坏，不能宣称形式化证明所有越界或 race 均不存在。

禁止使用只检查部分输出、只打印 tensor 或放宽 tolerance 的方式宣布 P3 PASS。

### 7.4 超时与错误

每项 ACL 调用均需检查 rc，并立即复制错误信息。

设置有限的 stream 同步超时及外层进程 watchdog。

外层超时、设备异常或 stream 同步失败均应产生明确的失败分类。

禁止对共享设备进行破坏性 reset，禁止清理其他用户的 NPU context、进程和日志。

所有物理 NPU 验收串行执行。
