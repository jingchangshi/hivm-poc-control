## 5. P4-B：PREBUILT 注入及 Runtime 集成

### 5.1 PREBUILT DeviceCodegen

新建一个显式 test-only DeviceCodegen 入口。

参考现有：

- `BuildTileLangAscend`
- `ExtractFuncInfo`
- `AscendModuleCreate`
- `global_func_device_codegen`

要求：

- 仍使用 TileLang 正常的 Lowering、Host CodeGen 和 Module import 路径。
- 不运行 AscendC Source CodeGen。
- 不运行 PTO CodeGen。
- 不运行 HIVM TIR→Late MLIR 生成。
- 仅从 P3 固定路径读取 Binary 并验证完整 SHA。
- 生成可被 Host Module import 的现有 Ascend Runtime Module。
- PREBUILT 模式必须有可审计的明确标签。
- 不能将该入口误报为真正 DeviceCodeGen E2E。

必须确认真正导入 Host Module 的设备 Module 就是注入了 P3 Binary 的 Module。

对 test-only callback、编译缓存和目标配置增加身份约束：错误 Binary、错误目标或错误 ABI 不得命中旧缓存而假 PASS。

### 5.2 FunctionInfo 与 Launch 配置

从实际 TileLang Prepared Device TIR 提取 FunctionInfo。

使用现有 `ExtractFuncInfo` 或等价的已有机制。

检查：

- function name 为 `main_kernel`。
- 正好三个设备指针参数。
- 参数顺序为 A/B/C。
- HostArgs size=24 bytes。
- kernel launch tags 包含 `blockIdx.x`。
- `tirx.use_dyn_shared_memory` 为正确的末尾 launch tag。
- grid 来源为 TIR 的 thread extent=64。
- dynamic UB 来源为 TIR 的 196608-byte 属性。

不能在 Runtime 的 HIVM 分支中直接把 grid=64 或 dynamic UB=196608 硬编码为固定常量。

允许 test fixture 对这些值建立断言，但正常 Runtime 必须从 FunctionInfo/LaunchParamConfig 读取。

冻结 Golden 的 target 元数据不能被就地修改。如 Backend selector 引入新的 key，应使用派生 IR 并证明除了目标选择之外没有改变语义。

### 5.3 关键：VECTOR_CORE Binary Loader

P3 已通过独立实机实验确认：

- E0：options=nullptr → DEVICE_FAULT。
- E1：VECTOR_CORE magic → PASS。
- E2：ENGINE_TYPE=AIV、无 magic → DEVICE_FAULT。
- E3：VECTOR_CORE magic + ENGINE_TYPE=AIV → PASS。
- E4/E5：错误 magic → DEVICE_FAULT。

因此 P4 新 HIVM Binary Module 必须使用：

`ACL_RT_BINARY_LOAD_OPT_MAGIC`

以及实际 CANN 9.2 头文件定义的：

`ACL_RT_BINARY_MAGIC_ELF_VECTOR_CORE`

请先检查：

- `src/ascend/runtime/ascend_module.cc`
- `src/ascend/stubs/ascendcl.h`
- `src/ascend/stubs/ascendcl.cc`
- CANN 9.2 实际 `acl_rt.h`

在保持 TileLang 当前 lazy CANN Stub 机制的前提下，实现最小加载选项。

要求：

1. 仅对显式 HIVM AIV Binary 启用 VECTOR_CORE。
2. 原有 AscendC Module 继续使用原有 Loader 行为。
3. 不把 ENGINE_TYPE=AIV 当作 VECTOR_CORE magic 的替代品。
4. Loader option 的结构体布局、枚举值和生命周期与真实 CANN ABI 对齐。
5. 提供 CANN 头文件级的 ABI 对照测试，避免手工定义错误。
6. 不直接修改其他不相关 Runtime。
7. 不影响原有 AscendC Binary 加载。
8. 错误 magic、缺少 magic 的负例先使用可控的 Stub/Mock 检验，不在共享设备上重复制造 P3 已确认的设备故障。

### 5.4 Module 序列化与 InspectSource

现有 `AscendModuleNode` 可序列化，但 `AscendModuleLoadFromBytes` 仅接受 `"aibin"`。

若新增 HIVM Binary 类型或 Loader mode：

- 必须使 Module 序列化和反序列化保留 HIVM 身份。
- 恢复后的 Module 仍必须选择 VECTOR_CORE。
- 原始 `"aibin"` 格式与旧缓存行为不变。
- 不能依赖不可序列化的进程局部状态或隐式环境变量选择 Loader。
- `inspect_source` 需要诚实标明 PREBUILT 来源，不得伪造 AscendC 或新生成 HIVM MLIR。
- 先确定最小兼容实现，不进行不必要的 Runtime 格式大重构。

Verifier 应分别验证直接创建 Module 和序列化后恢复 Module 的 Loader 行为。

## 6. P4-C：真实 TileLang → TVM-FFI → NPU

`vector_add(524288, mode="simd")`

使用显式 HIVM backend selection。

必须通过 TileLang 正常 Host 编译路径生成并调用 Host Module，而不是手写 P3 ACL Launch。

检查完整路径：

`TileLang program`
→ normal lowering
→ host/device split
→ prepared device TIR
→ HIVM PREBUILT injection
→ `AscendModuleCreate`
→ Host Module import
→ TVM-FFI
→ `AscendWrappedFunc`
→ `LaunchParamConfig`
→ VECTOR_CORE ACL loader
→ `aclrtLaunchKernelWithHostArgs`
→ Ascend950PR。

### 独立测试

沿用 P3 已冻结的独立输入和预期公式。

至少覆盖：

- 全零。
- 零+非零常量。
- 非零常量。
- 正负混合与不同量级。
- 每 block 不同的数据。

全量比较 524288 个 float32 输出，不允许只检查部分 tensor。

P4 验收应检查：

1. 实际进入了 HIVM BackendModule。
2. 实际发生 Host CodeGen。
3. Host Module 导入了正确 Device Module。
4. Device Module 包含冻结 SHA 的 P3 Binary。
5. 没有触发 AscendC/PTO Device CodeGen。
6. 没有调用 P2 编译器生成新二进制。
7. 真实 Loader 使用 VECTOR_CORE magic。
8. 使用由 FunctionInfo 推导的 grid=64。
9. 使用由 FunctionInfo 推导的 dynamic UB=196608。
10. 三个设备指针参数正确打包。
11. 所有 ACL launch/sync 操作成功。
12. 所有输出元素正确。
13. 没有 fallback 到旧 Runtime 或预构建 AscendC Kernel。

必须记录实际目标、Backend 名称、编译入口、加载参数、FunctionInfo、Binary SHA、执行日志及逐元素结果。

所有实机测试使用已获分配且空闲的 Ascend950PR device 0；不得触碰其他用户使用的 device 1。

如果设备分配发生变化，应先核对现场授权，不得自动换卡。

## 7. P4-D：负例、旧路径回归与终审

Verifier 独立覆盖：

### Backend routing

- AscendC、PTO、HIVM 三路互斥。
- 错误 target 组合明确拒绝。
- HIVM 不支持的 execution backend 明确拒绝。
- 非 HIVM 不会误进入 PREBUILT 路径。

### Binary 与 Runtime

- Binary SHA 错误拒绝。
- 旧缓存无法覆盖新的测试 Binary 身份。
- 错误 Kernel symbol 拒绝。
- FunctionInfo 参数个数、顺序或类型不匹配拒绝。
- 缺少必要 launch tags 或错误 tag 顺序拒绝。
- 错误 grid/dynamic UB 能被元数据断言发现。
- 错误 Loader magic 能被测试发现。
- 序列化/反序列化保持正确 Loader policy。
- ABI 错误不能被历史已成功运行的 P3 Binary 掩盖。

错误 magic 的负例优先采用 Mock/Stub，不重复真实设备故障。

### 旧 Backend 回归

至少运行受影响的 AscendC 与 PTO Backend selection、编译入口及 Runtime 代表性测试。

如果完整 E2E 因既有环境限制不可执行，标记 BASELINE_BLOCKED 或 NOT_RUN，提供相应证据。

不能把未运行的测试写为 PASS。

1. HIVM Backend 真正互斥。
2. PREBUILT 路径被严格隔离。
